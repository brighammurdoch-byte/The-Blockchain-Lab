Ethereum rules lab

Account balances, nonces, gas, and a tiny ERC-20-like LabCoin. Finance students can send ETH-units. Coding students edit Solidity-shaped source.

This is not solc and not the EVM. Real Ethereum contracts are compiled by solc to EVM bytecode and executed by clients such as geth (Go). Your browser does neither. The editor is Solidity that looks like a transfer contract. On Apply, a translator reads INITIAL_SUPPLY, BLOCK_REWARD, TRANSFER_GAS, and whether require(balanceOf[msg.sender] >= amount) is present, then a JavaScript account engine follows those rules. Remove the require and overdrafts succeed — the same class of experiment as breaking a Solidity check, not the same as deploying on mainnet.

What happens when you click Apply

  1. The page does not run solc or an EVM.
  2. A reader scans this Solidity for INITIAL_SUPPLY, BLOCK_REWARD, TRANSFER_GAS, BLOCK_GAS_LIMIT, and the require(balanceOf[msg.sender] >= amount) check.
  3. Those become the live JavaScript account model’s parameters.
  4. Transfers you send then follow the new rules. Changing INITIAL_SUPPLY only affects a rebuilt genesis (use Reset).
